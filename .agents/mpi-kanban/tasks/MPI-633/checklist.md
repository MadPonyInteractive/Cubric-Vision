# MPI-633 — checklist

## Phase 0 — MEASURE FIRST (both are acceptance criteria)

Nothing in `brief.md` about decode cost is sampled; it is reasoned from how browsers decode
video. Build nothing until these two numbers exist.

- [x] **M1 — per-video decode cost against resolution.** Same clip content, several
      resolutions (source 3000x1280 / 1080p / 720p / 480p), each promoted in an identical
      card box, sampled with `Get-Counter '\GPU Process Memory(*)\Dedicated Usage'` summed
      over the Vision PIDs, 3 s interval, **ComfyUI engine OFF** so the app is measured
      alone. Output: MB per promoted video per resolution → the proxy size is chosen from
      that curve, not from a 720-vs-480 preference.
- [x] **M2 — gallery VRAM at the largest card size vs the smallest.** Same project, same
      scroll tour, slider level 1 vs level 4, on TODAY's build (one 512px thumb at every
      size). This is the baseline the brief's arithmetic table claims is flat; if it is
      already lopsided the tier ladder has to answer for it.
- [x] Record both in `validation.md` with the raw CSVs named, the way MPI-631 did.

## Phase 1 — image renditions

- [ ] Rendition ladder chosen from M2 (a ladder, not the current single 512).
- [ ] Selection keys off the **rendered pixel box** (max of width/height) the justified
      packer already computes — NOT `ITEMS_PER_ROW_TARGET`, because three portrait cards per
      row are narrow but tall.
- [ ] Smallest rendition whose pixels >= the box; fall back to `filePath` when none is big
      enough.
- [ ] **Never generate above the source** — most assets here are 1280x800, so a large card
      uses the original file rather than an upscaled derivative.
- [ ] WebP for every image rendition, never JPG (MPI-627 — a JPG of a background-removed PNG
      hands back the original image whole, backdrop included).
- [ ] `extractImageThumb` already takes `width`; use the **returned** path, not the one
      passed.

## Phase 1b — image demote (ADDED by the M2 measurement, not in brief.md)

M2: a 1280px rendition at the largest card size costs **238 MB** resting after a scroll to
the bottom, against 12 MB today — but the no-scroll control is only **23.7 MB**. So 214 of
those MB are Chromium's GPU image cache RETAINING every card the scroll passed, not the
working set. Without this phase the quality fix costs 20x VRAM instead of 2x.

- [ ] A card demoted by the existing MPI-631 `DEMOTE_MARGIN_PX` observer swaps its image
      back down to the smallest rendition (or drops the src), and promotes back on scroll-in
      — the same hysteresis pair, not a second boundary.
- [ ] Re-measure the L4 + big-rendition config: resting must land near the 23.7 MB control,
      not near 238.

## Phase 2 — video proxy

- [ ] Proxy resolution set by M1.
- [ ] `_promoteVideo` mounts the proxy; the viewer still opens the full-res master.
- [ ] Proxy generated by the bundled ffmpeg through `services/ffmpegThumb.js` — no new
      dependency.

## Phase 3 — lifecycle

- [ ] Backfill for existing projects, MPI-319 pattern (`POST /backfill-image-thumbs` shape,
      fire-and-forget on project load, patch live items + rebuild the grid). Patch on
      value-differs, not on missing — an item holding a deleted URL 404s its card otherwise.
- [ ] Renditions live and die with the sidecar, same GC as today's thumbs; GC + delete paths
      accept every extension in use.

## Phase 4 — prove it

- [ ] Re-run M2 on the new build: largest card size not materially worse than smallest. A
      regression here means the tier selection is wrong.
- [ ] Unit test for the tier-selection rule (box in → rendition out, incl. the clamp to
      source and the fallback to `filePath`).
- [ ] Desktop spec if the promotion path changes — fixture must use REAL shipped media
      (`comfy_workflows/display/`); a made-up src 404s into the missing-media path and the
      spec reads as a broken fix.
- [ ] Mutation-test anything load-bearing (MPI-631: three mutations caught a fixture that
      was green for the wrong reason).
- [ ] `npm test`, `npx playwright test --config=playwright.desktop.config.js`, eslint,
      `validate_board.py .`
- [ ] `docs/gallery.md` documents the ladder + the selection rule;
      `docs/releases/UNRELEASED.md` gets an entry.
