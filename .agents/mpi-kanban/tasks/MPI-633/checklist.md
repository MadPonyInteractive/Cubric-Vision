# MPI-633 — checklist

## Phase 0 — MEASURE FIRST (both are acceptance criteria)

Nothing in `brief.md` about decode cost is sampled; it is reasoned from how browsers decode
video. Build nothing until these two numbers exist.

- [x] **M1 — per-video decode cost against resolution.** Same clip content, several
      resolutions (source 3000x1280 / 1080p / 720p / 480p), each promoted in an identical
      card box, sampled with `Get-Counter '\GPU Process Memory(*)\Dedicated Usage'` summed
      over the Vision PIDs, 3 s interval, **ComfyUI engine OFF** so the app is measured
      alone. Output: MB per promoted video per resolution → the proxy size is chosen from
      that curve, not from a 720-vs-480 preference.
- [x] **M2 — gallery VRAM at the largest card size vs the smallest.** Same project, same
      scroll tour, slider level 1 vs level 4, on TODAY's build (one 512px thumb at every
      size). This is the baseline the brief's arithmetic table claims is flat; if it is
      already lopsided the tier ladder has to answer for it.
- [x] Record both in `validation.md` with the raw CSVs named, the way MPI-631 did.

## Phase 1 — image renditions

- [x] Rendition ladder chosen from M2 — 512 + 1280, top tier per Fabio (2026-08-27: no point
      going lower). `IMAGE_RENDITION_PX` in `services/ffmpegThumb.js`.
- [x] Selection keys off the **rendered pixel box** (max of width/height, in DEVICE pixels)
      the justified packer computes — `card.el.setRenderBox`, called on every justified
      render so a slider move or a resize re-picks.
- [x] Smallest rendition whose pixels >= the box; falls back to `filePath` when none is —
      `pickImageRendition` in `js/utils/galleryRenditions.js`. Its own module because the
      grid imports `/js/utils/dom.js` by absolute browser path and Node cannot import it.
- [x] **Never generated above the source** — `writeImageRenditions` skips the large tier for
      a source at or under 1280, so those cards mount `filePath`.
- [x] WebP for every image rendition (MPI-627) — `extractImageThumb` unchanged on that.
- [x] Uses the **returned** path, not the one passed.

## Phase 1b — image demote — SHIPPED, BUT ITS PREMISE WAS WRONG

The demote works and returns **no VRAM**: 236.5 MB with it firing against 234.5 for the same
tour without it, while every off-screen card really had swapped back to its 512 thumb.
Chromium keys a decoded image by URL and holds it regardless of live references; no page API
evicts it. See `validation.md` § "The reversal".

- [x] A card demoted by the existing `DEMOTE_MARGIN_PX` observer swaps back down to the
      small rendition and promotes again on scroll-in — same hysteresis pair.
- [x] Re-measured. It does NOT land near the no-scroll control, and cannot: the acceptance
      criterion was written against a mechanism that does not exist.
- [x] **The replacement that does work — a scroll gate.** `promoteImage` refuses while
      `_isScrolling`; the existing 150 ms scroll-idle timer (MPI-321) sweeps the resting band
      via `_promoteVisibleImages()`. A fling past 120 cards paints 6 large renditions instead
      of 120: **73.8 MB against 241.5**, where the no-scroll floor is 72.9.
- [x] Demote kept deliberately — it bounds the working set and leaves off-screen entries
      unreferenced, hence discardable under real pressure. Its comment says exactly that, so
      the original expectation is not re-derived from it.

## Phase 2 — video proxy

- [x] Proxy resolution set by M1 — 720p (`VIDEO_PROXY_HEIGHT`), ~6x cheaper per promoted
      card than a 3000x1280 master.
- [x] `_promoteVideo` mounts `selected.proxyPath || filePath`; the viewer, drag-out and
      reveal read the item's `filePath` and are untouched.
- [x] Generated by bundled ffmpeg through `services/ffmpegThumb.js` — no new dependency.
      `writeVideoDerivatives` is called by all five video routes (import, save-generation,
      concat, crop, reverse) rather than each repeating the poster extraction.
- [x] Clamped: no proxy for a clip at or under 720p — the master IS the proxy. Verified at
      the boundary (480 skip, 720 skip, 721 encode, unknown encode).
- [ ] Not measured end to end: a rig run over a gallery of PROXIED clips. The mechanism is
      confirmed and M1 predicts the saving, but no sample exists.

## Phase 3 — lifecycle

- [x] Backfill for existing projects — `POST /backfill-media-derivatives` (renamed from
      `/backfill-image-thumbs`, which had stopped being true), fire-and-forget on project
      load, patching live items + rebuilding the grid. Converges: a derivative is only OWED
      by a source above its tier.
- [x] Patches on value-differs across all three fields, not on missing. The map is
      `{ itemId: { thumbPath, thumbPathLg, proxyPath } }` — the string value could not
      express an item whose `thumbPath` is already right and whose large rendition is the
      only new thing, which compares equal and never reaches the card.
- [x] Renditions live and die with the sidecar. GC + delete paths match `DERIVATIVE_RE`
      (`<id>.thumb.*` / `<id>.proxy.*`) by PREFIX — three extension lists had to be edited
      in lock-step before, and `(jpg|webp)` already failed `.1280.webp`.
- [x] Copy-item copies the large rendition and the proxy alongside the thumb.
