# Bump the shipped engine: ComfyUI v0.31.0 -> v0.34.0

Discovered 2026-08-28 while bumping the LOCAL authoring bench (G:/ComfyUi) from
v0.31.0 to v0.34.2. Everything below is MEASURED on that bench, not read off
release notes.

## Target tag: take v0.34.0, not the highest tag

GitHub Releases publishes **v0.34.0** (2026-08-26) as the newest release.
v0.34.1 and v0.34.2 exist as git tags carrying real "ComfyUI v0.34.x"
version-bump commits, but no Release object at all - so they are neither
prereleases nor published releases, just tags ahead of the release page. The
bench currently sits on v0.34.2 (harmless there). The SHIPPED pin should follow
the published release unless one has landed for a higher tag by the time this
card runs - re-check `gh api repos/comfyanonymous/ComfyUI/releases` first.

Delta v0.34.0..v0.34.2 is six commits, five of them irrelevant to us:

    02cfc879  [Partner Nodes] Google Omni 1.1
    51262bb3  chore: workflow templates -> 0.11.50
    c948d444  fix(video): remux HEVC to mp4/mov as hvc1 via hevc_mp4toannexb
    7597a5a0  ComfyUI v0.34.1
    a2f5ddee  [Partner Nodes] WAN3-Prime
    2e3eb2dc  [Partner Nodes] Recraft V4 Styles
    ae59fed0  [Partner Nodes] drop retiring Veo 2 / Veo 3.0

Partner nodes are cloud-API nodes; we run local, so they change nothing for us.
c948d444 (HEVC remux) is the only local-relevant commit in that range - reason to
prefer a higher tag ONLY if an HEVC path matters.

## What node_lock.json has to move

`dev_configs/node_lock.json` -> `comfyui.core.tag` + `comfyui.core.commit`, AND
both `comfyui.frontend` pins. Those two currently mirror v0.31.0's
requirements.txt exactly (1.48.7 / 0.11.34), so they must mirror the target's.

requirements.txt, v0.31.0 -> v0.34.0:

    comfyui-frontend-package     1.48.7   -> 1.49.6
    comfyui-workflow-templates   0.11.34  -> 0.11.48    (0.11.50 at v0.34.2)
    comfyui-embedded-docs        0.5.9    -> 0.5.10
    comfy-kitchen                0.2.28   -> 0.2.31
    comfy-aimdo                  0.4.13   -> 0.4.15
    av                           >=16.0.0 -> >=17.0.0

v0.34.0 -> v0.34.2 changes ONLY workflow-templates (0.11.48 -> 0.11.50).

## The two real risks

1. **av >=16 -> >=17 is a PyAV MAJOR bump.** Resolved to av 17.0.1 on the bench.
   It is the one line in the whole requirements diff that can break a video path
   (VideoHelperSuite, any ffmpeg-backed node), and it has to be satisfied inside
   the Pod image and the portable engine too, not just on a dev box. Smoke a
   VIDEO op, not only an image op.

2. **comfyui-workflow-templates is now a META-package.** 0.11.50 pulls seven
   subpackages: -core 0.3.326, -json 0.1.61, -media-api 0.3.84,
   -media-assets-01 0.1.36, -media-image 0.3.160, -media-other 0.3.229,
   -media-video 0.3.101. node_lock pins only the parent. Any offline or baked
   install (Pod image, portable bundle) must carry all seven or templates
   resolve empty. Check how the build actually fetches this before assuming the
   parent pin covers it.
